# Prime Orbit v0.1.22 — Reliable Steer and Follow-up delivery

Prime Orbit 0.1.22 fixes the lifecycle gap that could leave a Steer or Follow-up instruction above the composer after Prime Agent had already consumed it, while omitting the corresponding user turn from the conversation.

## Durable queue-to-transcript reconciliation

- Orbit now follows Prime Agent 0.8's complete queued-action lifecycle instead of treating the initial RPC acknowledgement as delivery.
- A queued row becomes a visible user turn when Prime Agent reports the action's durable `running` phase, even if the live user `message_start` event was missed during a reconnect or fast transition.
- Persisted Prime Agent history remains authoritative and replaces the temporary reconciliation at the next safe terminal boundary.
- Intentional same-text Steer and Follow-up instructions remain two separate actions. Prime Agent's steering-first priority selects only the action actually being delivered.

## Safe queue edits and deletion

- Queue mutations carry the complete lane snapshot that was visible when the action was requested. If the lane advances first, the mutation is rejected and resynchronized instead of applying the old index to a different instruction.
- Deleting a row during the exact moment it becomes active now removes the stale local queue presentation and keeps the delivered user turn, rather than showing `La session Prime Agent n’est pas active dans le daemon`.
- Delivered instructions are no longer presented as editable `Synchronisation…` rows.
