# Prime Orbit v0.2.1 — Fewer alarms, steadier state

Prime Orbit 0.2.1 is a reliability release. It removes the error messages Orbit was raising about its own bookkeeping, and stops conversations from getting stuck in states nothing could clear.

## Errors that were never yours

- Reads that only populate the inspector — model catalog, commands, session statistics, schedules, heartbeats — can no longer put a conversation into an error state. Their panel keeps the last known data and the conversation stays healthy.
- Whether such a read times out, is refused, or arrives while the daemon is disconnected no longer changes anything: Orbit now classifies the failure by the request it sent, not by the wording Prime Agent replies with. That wording varies by failure mode, and the daemon renames commands — `get_heartbeat` is reported as `heartbeat_get`, `list_schedules` as `cron_list` — so matching on it let a stream of cosmetic failures reach the interface as **Prime Agent needs attention**.
- Identical failures collapse into a single counted row. A disconnected daemon rejects every command of every bootstrap retry, and one row per rejection buried the timeline under dozens of identical entries.
- The post-maintenance refresh no longer waits on the model and command catalogs. It succeeds on state and history; a catalog that times out is not a broken conversation.

## Conversations that stayed connecting

- Leaving the loading state no longer depends on a `get_messages` response that may never have been requested. The bootstrap owns that state and clears it once it succeeds, so a retry, a runtime-mode switch, or a reattach cannot strand a conversation on **Connecting to Prime Agent** with its transcript already rendered behind the banner.
- An idle snapshot releases the loading state once a transcript is on screen, and a conversation that claims to be connecting while nothing is connecting it re-enters its bootstrap instead of waiting forever.

## State that matches Prime Agent

- A periodic reconciliation asks Prime Agent for its own state while a conversation claims to be working, or while it still shows rows nothing has updated. Every previous recovery path fired on a cue that itself travelled through the event stream, so none could repair the loss of that cue.
- Lifecycle rows such as **Prime Agent réfléchit** now close at an authoritative idle boundary and when the process exits. They were only ever closed for tool executions, so a lost terminal event left them spinning with no process left to end them.
- Corrections Orbit had to apply on its own are recorded and shown in the session inspector, so a lost event is no longer indistinguishable from a slow agent.
- A new **Resynchronize** action re-reads state and history without disturbing operations that have a real awaiting caller.

## Plan mode

- A question whose options carry only a label, or only a value, is asked instead of failing validation. Each field now defaults to the other, which removes a full retry round-trip and the failed step it showed.
- Handoff verification reads the flag its own transcript source writes. For a published session it tested the RPC projection after reading the local journal, so it could never succeed and reported an unavailable history while the plan was in fact running.
- The Plan replay probe no longer re-runs a full bootstrap eight times a second while the runtime is simply not in Plan mode. Each bootstrap replays the native dialog queue, which inflated a single Plan row past 1400 updates and stalled the interface.

## Runtime awareness

- A runtime reporting a version Prime Orbit was not validated against is surfaced in settings. Orbit's bridges bind to Prime Agent's daemon internals, so an unvalidated version is a real risk rather than a silent one.

## Validation

Validated with 297 frontend tests, 226 native tests, TypeScript, the production Vite build, Rust formatting, strict Clippy, and the Rust 1.88 dependency graph.
