# Prime Orbit v0.1.16 — Transactional Prime Agent 0.7.4 upgrades

Prime Orbit 0.1.16 upgrades its managed runtime to the verified official Prime Agent 0.7.4 release. It prepares updates side by side, exposes Prime Agent's real main-agent defaults, and adds honest advisory preferences for future RLM delegations.

## Highlights

- Managed installation is pinned to the official Prime Agent `v0.7.4` tag and exact verified commit.
- A new managed runtime is cloned, installed, built, given its own Python kernel environment, and checked with `--version` before Prime Orbit selects it.
- If preparation fails, the previous runtime configuration remains selected. The updater does not overwrite loaded files in place, avoiding the Windows `EPERM` failures that could interrupt an upgrade while an older generation was still running.
- Every versioned managed runtime generation receives a stable private daemon socket. All Prime Orbit windows using that generation converge on the same daemon, while side-by-side generations cannot cross their queue, reload, or restart traffic.
- The General settings page now reads and writes Prime Agent's official global default provider, model, and thinking level. Writes are validated, locked, backed up, and atomic; unrelated settings and secrets are never returned to the interface.
- New conversations inherit those main-agent defaults unless a project or conversation has a more specific model choice.
- Separate sub-agent preferences can suggest a model and, with Prime Agent 0.7.4 or newer, a thinking level for future `rlm.run` calls.

## RLM preferences are advisory

Prime Orbit stores RLM preferences locally and captures them when a new conversation is created. They are passed to Prime Agent as a bounded system-prompt addition, not as a guaranteed router override. Prime Agent may use another compatible model when the preference is unavailable and should report that fallback. Existing conversations keep the preference snapshot they were created with.

## Update and managed-runtime test

Version 0.1.15 can discover this release through **Settings > About**:

1. Select **Check for updates** and download version 0.1.16.
2. Choose **Restart and update** when open Prime Agent sessions are ready to stop.
3. After Prime Orbit restarts, open an existing conversation and keep its Prime Agent session active.
4. Open **Settings > Prime Agent** and select **Managed installation** to prepare Prime Agent 0.7.4. The existing session remains attached to its current generation, and subsequent session starts use the newly verified runtime after activation.
5. In **Settings > General**, save a main-agent model/reasoning default and optional RLM preferences, then create a new conversation to test the captured values.

Neither the Prime Orbit updater nor managed Prime Agent installation runs automatically. Installing the application update still requires confirmation, and switching the managed runtime happens only after the new candidate passes every activation check.

## Validation

- Targeted coverage exercises side-by-side activation, failure preservation, exact Prime Agent version checks, daemon generation isolation, global settings writes, and advisory RLM preference snapshots.
- The signed Windows workflow rechecks frontend tests and production build, Rust tests, formatting, strict Clippy, Rust 1.88 compatibility, updater signatures, uploaded asset digests, and installer checksums before leaving a draft for review.

Prime Orbit is an independent community client built around Prime Agent. RLM preferences are guidance rather than enforced routing, and the application does not weaken Prime Agent's permission boundary or claim operating-system sandboxing.
