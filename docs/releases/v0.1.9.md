# Prime Orbit v0.1.9 — Windows runtime repair

Prime Orbit 0.1.9 repairs the managed Prime Agent installation path on Windows. It fixes Python kernel setup, suppresses unwanted console windows from managed runtime children, and prevents the Windows session-lease collision from trapping daemon workers in a restart loop.

## What changed

- Managed installations are pinned to the verified stable Prime Agent `v0.7.3` tag and exact official commit instead of following a moving beta/main checkout.
- Prime Agent's POSIX-style `kernel-venv/bin/python` path is mapped to the Windows `kernel-venv/Scripts/python.exe` interpreter when appropriate.
- Managed Node child processes, including Python, `uv`, PowerShell, Bash, and daemon workers, are launched without visible console windows.
- The exact Windows `EPERM` session-lease rename collision is normalized so Prime Agent's own guarded live/stale-owner logic can run.
- Managed setup now prepares and validates the Python kernel before reporting success.
- The generated model catalog changed by Prime Agent's build is restored atomically, keeping the managed checkout clean and updateable.

The compatibility layer is limited to Prime Orbit's managed source runtime. External Prime Agent executables and user-owned installations are not patched.

## Upgrade instructions

1. Close Prime Orbit 0.1.8 completely.
2. Install Prime Orbit 0.1.9 using the recommended `.exe` installer.
3. Open **Settings → Prime Agent** and run **Managed installation** once if the runtime is not already reported operational.
4. Retry the affected conversation and Python execution.

The installer is not yet code-signed and may trigger a Windows SmartScreen warning. Verify the SHA-256 value above before running it.
