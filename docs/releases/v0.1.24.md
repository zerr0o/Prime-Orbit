# Prime Orbit v0.1.24 — Audit hardening (beta)

Prime Orbit 0.1.24 applies the first wave of fixes from a full security and reliability audit of the codebase. This build is released as a beta-quality draft while the remaining audit findings are scheduled.

## Reliable conversation state

- A failed prompt submission no longer leaves the conversation permanently marked as busy. When Prime Agent rejects or cannot receive a queued message, the optimistic message is rolled back and later prompts start normal turns again instead of being silently forced into queue-only delivery until restart.
- Stopping an agent now terminates the RPC client before releasing its slot. A failed termination keeps the conversation visible and retryable instead of orphaning a live process behind a freed identifier, and a concurrent emergency restart can no longer have its slot stolen mid-flight.

## Stronger process ownership

- `stop_agent` now enforces window ownership like every other agent lifecycle command. A window that never attached to a conversation can no longer stop an agent that another window is actively using; conversations whose owners all detached remain stoppable by any window so idle cleanup still works.

## Tighter history containment

- Loading session history now requires the transcript file to live inside a known Prime Agent sessions root in all cases. Knowing a session's internal identifier no longer widens which files on disk the application can be pointed at. Configured agent directories (`PRIME_AGENT_CODING_AGENT_DIR` / `PI_CODING_AGENT_DIR`) are honored as valid roots alongside the default location.

## Interface correctness

- Stacked dialogs no longer fight over keyboard handling: only the topmost modal responds to Escape and owns Tab focus trapping, so a confirmation opened above another dialog closes exactly one layer per press and background controls stay out of the tab order of hidden dialogs.
