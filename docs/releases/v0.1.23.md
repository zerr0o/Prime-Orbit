# Prime Orbit v0.1.23 — Queue cleanup and safe update restart

Prime Orbit 0.1.23 removes stale Steer and Follow-up rows cleanly after Prime Agent has already left the active queue, and makes application updates wait for Orbit's managed Prime Agent daemon to stop completely before restarting.

## Reliable queued-message deletion

- Deleting an orphaned Steer or Follow-up entry no longer reports `La session Prime Agent n’est pas active dans le daemon`.
- When the queued action has crossed its delivery boundary and the daemon session is no longer active, Orbit removes the stale local row and resynchronizes the conversation presentation.
- Editing or reordering an instruction after the active session disappears remains blocked with a precise explanation, preventing an old queue index from targeting unrelated work.

## Safe application updates

- Prime Orbit now stops all of its RPC clients before installing an update, then requests shutdown of the exact private daemon owned by the managed runtime.
- Installation continues only after the private daemon socket has stopped accepting connections. A shutdown acknowledgement by itself is not considered sufficient.
- If the daemon remains reachable, the update is cancelled instead of restarting into a partially stopped Prime Agent runtime.
- External or system Prime Agent daemons are never terminated by this mechanism.

- TypeScript, Rust 1.88 compatibility, strict Clippy, formatting, and the production frontend build pass.
- The update shutdown path was exercised against a real isolated Prime Agent 0.8 daemon on Windows: the bridge confirmed `stopped`, the daemon process exited, and its private socket disappeared.
