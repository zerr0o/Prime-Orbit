# Prime Orbit v0.2.0 — Prime Agent control and recovery

Prime Orbit 0.2.0 makes Prime Agent sessions easier to find, safer to resume, and considerably more reliable during long-running or interactive work.

## Every Prime Agent conversation

- **Conversations Prime Agent** now lists every root session discovered in Prime Agent's configured storage, including conversations created from a terminal or another client.
- Search by title, first message, folder, or session identifier, then filter by activity, attention, archive state, or external origin.
- External conversations open in a read-only transcript reader. Prime Orbit never authorizes or adds their folder automatically.
- **Add this folder to Prime Orbit** explicitly creates or links the project before enabling the normal interactive workspace.

## Exact session recovery

- Prime Orbit can reattach to the exact daemon-owned RPC session when the original UI connection was lost, instead of creating a conflicting duplicate process.
- Canonical transcript history remains visible while an inactive or temporarily unreachable session is repaired.
- Sessions whose folder moved or disappeared remain readable and clearly explain why they cannot yet be resumed.

## Reliable Plan questions and queues

- Pending Plan questions survive WebView reloads and RPC reconnection through a bounded native cache tied to the exact conversation, session file, and session id.
- Reattachment buffers Prime Agent events emitted during the attach handshake, so restored question forms reach the interface instead of remaining on `Awaiting result`.
- Stopping a blocked Plan turn now resumes Prime Agent's suspended input queue before retrying recovery, avoiding the previous `queued session input is suspended` dead end.
- When a form truly cannot be reconstructed, the conversation shows a deliberate recovery action rather than an indefinite activity state.
- Lost Plan reviews are recovered too: Prime Orbit replaces only the detached RPC client, verifies the new connection, then offers to resubmit the same plan when Prime Agent is waiting for an apply, keep, or revise decision.
- Orbit's bounded recovery instruction remains internal instead of appearing as a fake user message in the conversation.
- A direct prompt remains visible as soon as Prime Agent accepts it, then adopts the durable native message identity without duplicating the turn. Steering and follow-up rows still come only from Prime Agent's queue.

## Safety and validation

- Native catalog reads attest the indexed file, Prime Agent storage root, session identifier, and file fingerprint before returning a bounded public transcript projection.
- Sub-agent sessions, empty drafts, forged catalog keys, links outside trusted roots, and oversized inputs remain excluded or rejected.
- Validated with 240 frontend tests, 205 native tests, TypeScript, the production Vite build, Rust formatting, strict Clippy, and the Rust 1.88 dependency graph.
