# Prime Orbit v0.1.19 — Session tools, model favorites, and Windows spelling

Prime Orbit 0.1.19 makes long-running sessions easier to manage, improves model selection, and restores native Windows spelling suggestions inside the themed composer menu.

## Session memory and refinement tools

- The Session inspector now loads the active session's existing memory entries and refinement history instead of showing only newly observed events.
- Memory and refinement entries have contextual actions to open their real file, reveal the containing folder, and perform safe maintenance operations.
- Deleting a memory requires confirmation, verifies the exact session entry, creates a backup, and uses an atomic native write.
- Applied refinements can be rolled back through an append-only inverse operation while preserving the original journal history.
- Session memory refreshes automatically after a refinement completes.

## Reliable resource reload

- **Reload resources** now resolves the exact active daemon session without turning the action into a prompt.
- The native bridge reuses the session owner's RPC identity with a fresh command namespace, avoiding inactive-session errors and accidental replay of a prior journaled result.
- Busy, incompatible, missing, and still-pending sessions produce distinct feedback instead of a false success.

## Faster model selection

- Models can be marked as favorites and remain at the top of every shared model list.
- Favorite order persists across restarts and merges safely when multiple Prime Orbit windows update it.
- The default-model and preferred-subagent-model selectors in **Settings > Models** now include the same searchable picker used in conversations.
- Each project in the workspace sidebar has a direct, keyboard-accessible new-conversation action.

## Composer and session resilience

- Prime Orbit's themed right-click menu now queries the installed Windows dictionary and shows real spelling suggestions with exact Unicode-aware replacements.
- A session that is merely connecting no longer queues its first prompt as a follow-up.
- Older idle snapshots cannot erase a newer prompt admission, and a ready empty conversation no longer falls back into local-history loading.
- Parent-managed subagent shutdowns are displayed as normal closures rather than failures.
